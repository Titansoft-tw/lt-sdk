# LtTelemetry (iOS, #4)

OTLP/HTTP JSON log encoding and delivery for lt-observability. Swift package target `LtTelemetry` (iOS 17, also builds
on macOS 14 so `swift test` runs on the Mac). Depends on `LtDeviceInfo` and re-exports it (`@_exported import`), so
`import LtTelemetry` is enough.

```swift
let telemetry = LtTelemetry(TelemetryConfig(
    logsUrl: Bundle.main.object(forInfoDictionaryKey: "LtTelemetryUrl") as? String, // full URL; empty = off
    headers: { ["Authorization": "Bearer \(token)"] },
    requireHttps: !isDebugBuild,
    serviceName: "lt-call-demo",
    device: info.staticDevice,
    storageDir: appSupport.appendingPathComponent("telemetry"),
    log: { print($0) }))                                    // only on delivered <-> failing changes, never the URL
let ctx = TelemetryContext(info.network(), info.audioRoute(), info.deviceState())
telemetry.send([Telemetry.qualitySecond(leg, metrics, atEpochMs: now, context: ctx)])
telemetry.writeCallMarker(marker.encode())                  // nil clears it; readCallMarker() at launch
```

`LtTelemetry`'s API is `@MainActor`, like the app's controller; `send` writes to the disk queue before it returns, and delivery runs in a `Delivery` actor off the main actor (so the startup-crash wait can block the initializer without a deadlock). URLSession is ephemeral with a 5 s resource timeout.

| File | What |
|---|---|
| `Telemetry.swift` | `TelemetryRecord`, `TelemetryLeg`, `TelemetryContext`, `AudioMetrics`, `LabTag`, record builders, `logsJson`, `scrub` |
| `AppTelemetry.swift` | `Severity`, `ErrorDomain`, `AppError`, `RelayHttpError`, `ApiErrors`, `SignalingErrors`, `MicEvent`, `MicInterruption`, `DeviceWatch`, `AppErrorTally`, `CallMarker` |
| `TelemetryStore.swift` | On-disk queue, same rules as Android's `TelemetryStore.kt` (segments of ≤ 200 records, lanes critical → event → bulk for send and eviction order, 5 MB / 7 days, `log.record.uid`, dropped counts); one JSON record per line |
| `RemoteTelemetryConfig.swift` | `TelemetrySettings`, `ConfigTarget`, `RemoteTelemetryConfig.parse` (schema 1, clamps, rules, local rollout bucket; a JSON boolean is never a number), `QualitySampling` |
| `PushTelemetry.swift` | `PushErrors`, `CallKitAudioWatch` |
| `MetricKitReport.swift` | hangs / crashes → `app_error`, `app_exit_daily` (payloads come from LtDeviceInfo's `MetricKitSource`) |
| `CallSetup.swift` | `SetupStage`, `AgoraCodes` |
| `LtTelemetry.swift` | `TelemetryConfig`, transport (same rules as Android #3: disk queue, backoff 10 s → 5 min ±20% or `Retry-After`, `observedTimeUnixNano`, drop report, legacy `telemetry-durable.json` import, `writeHeld` / `takeHeld`, `flush`, `drain(timeoutMs:)`, startup-crash wait, remote config with ETag and `config_version`) |
| `Lab.swift` | `LabTelemetry` (`net_probe`, `path_trace`, `case_result`), `PathTrace.compact`; the ICMP trace stays in the app |
| `Contract.swift` | Generated by `lt-telemetry-contract/generate.js`; do not edit |
