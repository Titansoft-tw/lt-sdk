# lt-telemetry-android (#3)

OTLP/HTTP JSON log encoding and delivery for lt-observability. Package `com.tswork.lt.telemetry`, minSdk 26, depends
on `lt-device-info-android` (exposed as `api`). No OkHttp or coroutines: `HttpURLConnection` on one daemon thread.

```kotlin
val telemetry = LtTelemetry(TelemetryConfig(
    logsUrl = BuildConfig.TELEMETRY_URL,                  // full URL, e.g. https://otel.example/v1/logs; blank = off
    headers = { mapOf("Authorization" to "Bearer $token") },
    requireHttps = !BuildConfig.DEBUG,
    serviceName = "lt-call-demo",
    device = deviceInfo.staticDevice,
    storageDir = context.noBackupFilesDir,
    log = { Log.i("App", it) },                           // only on delivered <-> failing changes, never the URL
))
val leg = TelemetryLeg(callId, channel, user, engine = "agora", sdkVersion = "agora-4.7.0")
val ctx = TelemetryContext(deviceInfo.network(), deviceInfo.audioRoute(), deviceInfo.deviceState())
telemetry.send(listOf(Telemetry.qualitySecond(leg, metrics, System.currentTimeMillis(), ctx)))
telemetry.writeCallMarker(CallMarker(...).encode())       // null clears it; readCallMarker() at launch
```

| `lab/LabTelemetry.kt` | `net_probe`, `path_trace`, `case_result`, `PathTrace.compact` (running the trace stays in the app) |
| `Contract.kt` | Generated by `lt-telemetry-contract/generate.js`; do not edit |

Extracted from lt-call-demo `rtc/Telemetry.kt`, `rtc/AppTelemetry.kt`, `rtc/PushTelemetry.kt`, `rtc/CallSetup.kt` and
the transport in `CallEnvironment.kt` (`AndroidCallEnvironment`). Left in the app: `Telemetry.connectivity()` (needs the
app's `Provider`), `CallIdAgreement` / `CallIdMessage`, `PathTrace.run`. Differences: `logsJson` takes the
`serviceName`; there is no device-wide `sdk_version`, so a record without an engine (`app_start`) no longer sends a
blank one. Not yet (plan §6): `CallTelemetry`, `setup_id`, clock offset, `onRecord`, `launched()`.
